# تصميم إعداد الأصناف والوصفات

المسار: `/purchases/catalog` ضمن قسم المشتريات؛ لا يضيف قسمًا رئيسيًا خامسًا. توجد روابط فرعية لسجل الاستلام وأرصدة الخام والكتالوج، ولا تتجاوز الأقسام الرئيسية الأربعة. المالك والمدير فقط يدخلان إعداد البيانات الحالية.

## ترتيب العمل

1. الأنواع والأصناف: إدخال اسم النوع فقط، ثم فتح أصنافه.
2. إضافة الصنف: الاسم وفئة خام/نهائي؛ النوع موروث من الصفحة والرقم يولد تلقائيًا.
3. المورد: الاسم فقط إلزامي، ووسيلة التواصل اختيارية.
4. وصفات المنتج النهائي: إدخال خام من قائمة نوع ← صنف، ثم سياسات التخمير والفرن. جميع الإصدارات مسودات واضحة. النسخ إلى إصدار جديد يجلب بيانات الخام الحالية ويملأ السياسة السابقة تلقائيًا؛ إذا عُطل الخام أو نوعه يطلب اختيارًا نشطًا جديدًا.
5. لا توجد أزرار حذف؛ التعطيل يحفظ التاريخ. فئة الصنف والنوع لا يتغيران بعد الإنشاء.

## الاتساق وحالات الواجهة

تستخدم الواجهة ألوان وخط ومكونات الأساس في [FOUNDATION.md](FOUNDATION.md). العناوين وحالات الخطأ عربية، والاتجاه RTL. الحوار يستخدم dialog أصليًا مع تركيز وحصر تفاعل داخله وإغلاق Escape عند عدم وجود إرسال جارٍ. النماذج ذات labels، وتنبيهات الحالة role=status والأخطاء role=alert.

القوائم: تحميل، فراغ، خطأ مع إعادة محاولة، بحث، نشط/معطل، وصفحات. الزر لا ينفذ طلبًا ثانيًا عند الحفظ. عند فقد الرد يبقى الطلب المعلق ولا يُسمح بعملية جديدة قبل التحقق/إعادة إرسال الطلب الأصلي. عند تعارض نسخة يغلق النموذج ويحدث القائمة؛ يعيد المستخدم فتحه بالنسخة الجديدة.

بيانات الصفحة الأولى من الخادم مباشرة بعد فحص الجلسة. SWR يجلب تغييرات القائمة دون polling دائم؛ بحث مؤجل 300ms وحد 25 عنصرًا مع cursor. قوائم اختيار المواد نفسها قابلة للبحث والصفحات، ولا تحمل الكتالوج كاملًا. تغيير النوع يصفر الصنف ويعيد مكون قائمة الأصناف كي لا يحمل خيارات النوع السابق.

## التحقق وحدوده

اختبار المتصفح يغطي النوع ثم الصنف، استبعاد المنتج النهائي من خيارات الخام، إنشاء إصدار ونسخه والاحتفاظ بالسابق، المورد، فقد الرد، التعارض، والصلاحيات. لقطات الهاتف بعرض 390 والمكتب 1280 محفوظة في screenshots. لا يمثل ذلك اختبارًا كاملًا بقارئ شاشة أو تجربة تشغيل ميدانية للعامل.

المدد المعروضة في اللقطات بيانات اصطناعية للاختبار فقط، وليست وصفات صناعية مقترحة.
