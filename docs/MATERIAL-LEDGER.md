# دفتر المواد والاستلام: التنفيذ الحالي

هذه الشريحة تنفذ استلام المواد الخام والأرصدة الافتتاحية وعكس الاستلام غير المستخدم. أضيف التخمير والسحب الجزئي بالترحيلات 007/008؛ التفاصيل في [دليل التخمير](FERMENTATION.md). التحويل التصنيعي والبيع غير منفذين. راجع العقد العام في [MATERIAL-CONTRACT.md](MATERIAL-CONTRACT.md) قبل توسيعها.

## المسار الفعلي

1. المالك أو المدير يختار المورد، ثم النوع والصنف الخام، ويدخل الوزن الصافي. مرجع المورد والملاحظة اختياريان في المشتريات.
2. يدعم السند 1–25 مادة مختلفة. يمكن تكرار المادة في سند آخر، لكنها لا تتكرر داخل السند نفسه. لا توجد مدد أو أسعار أو ضرائب مفترضة.
3. الخادم يتحقق من تطابق النوع والصنف ونشاط المورد والنوع والصنف. الاسم والفئة والوحدة والوقت لا تؤخذ من العميل.
4. معاملة واحدة تحفظ السند والبنود ودفعات المصدر والحسابات والحركة والأرصدة والتدقيق وoutbox ونتيجة الطلب. لا تظهر كمية قبل التزام المعاملة.
5. صفحة أرصدة الخام تعرض الأرصدة الموجبة لكل دفعة، وتربطها بسند الاستلام. الأسماء التاريخية لا تتغير بعد تعديل الكتالوج.

لا يُسجل شراء أسطوانة الغاز أو مستهلكات بالعدد كجرامات خام. واجهة المستهلكات والوحدات العددية لم تنفذ بعد. لا توجد مشتريات مواد نهائية أو واجهة مالية في هذه الشريحة.

## الجداول والقيود

الترحيلان 004 و005 يضيفان receipts، receipt_lines، material_lots، material_accounts، material_balances، material_movements، movement_lines، outbox_events.

- حساب المادة الحالي إما raw_lot_id مرتبط بـ FK مركب مع product_id، أو طرف نظامي external_kind=receipt مرتبط بالصنف. قيد XOR يمنع الملكية المزدوجة. أضيفت ملكية fermentation_id وstage_run_id بترحيل 007 مع FK مركب وقيد XOR موسع.
- لكل دفعة حساب واحد بوحدة g. الأطراف الخارجية لا تُعرض كمخزون. يمكن أن يكون رصيدها سالبًا لتمثيل دخول مادة من خارج المصنع.
- الكميات تنتقل كسلاسل عشرية بدقة 3 منازل. تقبل الواجهة الأرقام العربية والفاصل العشري العربي، وترفض فواصل الآلاف والدقة الزائدة دون تقريب.
- خطوط الحركة تستخدم NUMERIC مع تحقق scale قبل القبول، وليس cast قد يقرب وزنًا غير مسموح. الرصيد NUMERIC(18,3)، والحساب في الخدمة باستخدام BigInt بوحدة الملليجرام.
- الحركات والخطوط والدفعات والبنود والحسابات وأحداث outbox لا تعدل ولا تحذف بحساب التطبيق. لا يمكن إلحاق خطوط بحركة أو سند ملتزم سابقًا.
- قيد مؤجل حتى COMMIT يتحقق من توازن كل حركة لكل صنف، ومن أن الحركة العكسية تنفي الأصل بالضبط. التحويل بين خام ودهن يحتاج عقد تحويل منفصل وتوسعة القيد؛ لا تمرره كنقل عادي.
- قيد مؤجل آخر يربط سند الاستلام ببنوده ومصادره وكمياته وحركته وحدثه، ويرفض سندًا ناقصًا أو عكس حالة دون حركة وحدث.
- الرصيد يتحدث من trigger داخل نفس المعاملة. صلاحيات التطبيق لا تسمح بتعديل الرصيد أو نسخته مباشرة؛ دالة محدودة الصلاحيات تتيح قفل صفوف الأرصدة فقط، دون فتح صلاحيات التعديل.

## ترتيب الأقفال والتعافي

- كل أمر يبدأ بفحص العضوية الحية ثم حجز مفتاح الطلب، قبل إعادة أي نتيجة قديمة. أوامر الافتتاحي تتطلب دور المالك الحالي حتى عند إعادة الإرسال.
- الاستلام يقفل المورد ثم الأنواع مرتبة بالمعرف ثم الأصناف مرتبة بالمعرف. ينشئ الأطراف الخارجية بترتيب الصنف لتجنب عكس ترتيب الأقفال المتزامنة.
- العكس يقفل السند، ثم جميع الأرصدة المتأثرة مرتبة بمعرف الحساب. postMovement يستخدم الترتيب نفسه. الأقفال لا تنتظر تفاعل المستخدم أو اتصالًا خارجيًا.
- UUID الطلب وجسمه يحفظان محليًا قبل الإرسال، بنطاق الحساب. الحفظ المجهول النتيجة يُستعلم عنه أو يعاد بالمفتاح والجسم الأصليين. لا تغير expected_version عند إعادة الطلب.
- إعادة أمر إنشاء بعد عكسه تعيد نتيجة الإنشاء الأصلية دون إعادة الكمية. اقرأ تفاصيل السند لمعرفة حالته ورصيده الحاليين؛ نتيجة idempotency إيصال للأمر الأصلي وليست تقريرًا حيًا.
- لا يوجد إرسال دون اتصال، ولا إعادة إرسال تلقائي بعد انقطاع طويل. تمنع الواجهة إدخال حركة جديدة حتى حسم الطلب المعلق في نفس المجال.
- outbox يحفظ الأحداث مع المعاملة؛ عامل تسليم الإشعارات وجدول المحاولات لم ينفذا بعد. حفظ الحدث لا يعني وصول إشعار للعامل.

## العكس والتصحيح

زر عكس الاستلام يحتاج سببًا ونسخة السند. ينفذ حركة عكسية موثقة، ويبقي الكميات الأصلية والأسماء ووقت الاستلام. لا يعكس إذا تغيرت نسخة أي رصيد خام بعد دخوله الأول، حتى لو أعيدت إليه الكمية لاحقًا. هذا يمنع إلغاء مصدر استخدمته معالجة أخرى.

عكس الرصيد الافتتاحي للمالك فقط. التصحيح بعد الاستخدام، والمرتجعات الجزئية، وسند التصحيح المرتبط بالأصل، ضمن T18 ولم تنفذ هنا.

مرجع المورد غير الفارغ فريد للمورد، ويبقى محجوزًا بعد العكس. يمنع ذلك إعادة إدخال السند نفسه؛ لإعادة تسجيل إدخال خاطئ حاليًا يستخدم مرجع تصحيح واضح مع ذكر الأصل في الملاحظة. إعادة استخدام المرجع الأصلي ضمن عملية تصحيح مترابطة تحتاج خدمة T18، ولا تعتبر قائمة العكس بديلًا عن هذه الخدمة.

## المطابقة والموارد

```bash
npm run materials:check
```

الأمر يقرأ مجموع خطوط كل حساب ويقارنه بالرصيد في لقطة SQL واحدة. النجاح يعني عدم وجود فرق في البيانات الموجودة، وليس اختبار صحة جميع المراحل المستقبلية. الفشل يعرض أول 100 فرق وينهي بخروج 1؛ لا يصلح البيانات أو يعيد بناءها تلقائيًا. إعادة البناء الخاضعة للرقابة ما زالت ضمن T07/T27.

تستخدم الواجهة SSR للصفحة الأولى وSWR عند البحث والتركيز واستعادة الاتصال، دون polling دائم. كل قائمة ترجع 25 سجلًا مع cursor، والبحث مؤجل 300ms. تفاصيل السند استعلام واحد يعطي لقطة متسقة للرأس والبنود والأرصدة. الصفحات لا تجمع أوزانًا باستخدام JavaScript Number. لا حزمة أو خدمة إضافية لهذا التنفيذ.

## الحدود التشغيلية

- وقت التسجيل تلقائي ويعرض UTC صراحة؛ لا إدخال بتاريخ رجعي قبل إعداد توقيت المصنع وسياسة الفترة.
- دقة 0.001 جم قرار تطوير قائم؛ يجب مطابقتها مع الميزان الحقيقي قبل T29.
- توجد حسابات تخمير وأجزاء تنتظر الفرن؛ لا توجد مواقع متعددة أو حجز جودة أو ناتج نهائي بعد. كل ذلك يضيف مالكًا وFK وقيودًا وحركات واضحة، دون إعادة تفسير حساب خام قديم.
- هذه صلاحيات إدارة الاستلام؛ تفويض العامل للمشتريات لم يعتمد أو ينفذ بعد.
- اختبارات السحب الأصلية تستخدم primitive داخليًا؛ أضيفت اختبارات خدمة السحب الفعلية والمتصفح في شريحة التخمير. لا يوجد API عام لإنشاء نقل اعتباطي أو خصم مخزون.
