# سجل تقدم التنفيذ

آخر تحديث: 2026-11-05.

## الحالة الحالية

بدأ التنفيذ بناءً على طلب المتابعة بعد مراجعة Astra. النسخة المحلية تشمل الدخول والصلاحيات والأصول والأنواع والأصناف والموردين ومسودات الوصفات بإصدارات ثابتة، مع قاعدة PostgreSQL فعلية. أضيف استلام المواد الخام والأرصدة الافتتاحية وعكس الاستلام غير المستخدم وأرصدة دفعات الخام. أضيفت إعدادات المصنع واعتماد الوصفة والتخمير والفحص والسحب الجزئي. تشغيل الفرن والتوقف والاستئناف والتقارير لم تنفذ بعد. لا يوجد نشر إنتاجي أو بيانات مصنع حقيقية.

- مراجعة Astra سمحت ببدء الأساس مع استكمال تفاصيل المجال أثناء التنفيذ. صُححت ملاحظتا انتظار الفحص ونهاية التوقف، ومصدر expected_version في المواصفات.
- قاعدتا التطوير والاختبار منفصلتان، ومستخدم التطبيق محدود، والترحيلات باتصال إداري مستقل.
- واجهتا الأصول والكتالوج تحفظان وتعدلان وتعطلان وتبحثان؛ الأرقام والوقت والمستخدم تلقائية. اختيار أصناف نوع آخر لا يخلط القوائم.
- مسودات الوصفة تربط خامًا بمنتج نهائي، وتحفظ السياسة والأسماء بإصدار غير قابل للتعديل. النسخ إلى إصدار جديد يملأ البيانات السابقة تلقائيًا؛ اعتماد المالك وتفعيل وصفة واحدة للدفعات الجديدة منفذان، دون تغيير التاريخ.
- [عقد المواد](MATERIAL-CONTRACT.md) يحدد ملكية الرصيد والتحويل وإعادة المعالجة والتعافي للخدمات التالية. [OpenAPI](openapi.json) يغطي المسارات المنفذة، ويولد من العقود ويفحص بواسطة npm run api:check.
- حفظ ذري مع تدقيق وidempotency ونسخة تمنع الكتابة فوق تعديل أحدث، واستعادة نتيجة الطلب بعد فقد الرد.
- لم يُنشأ حساب مالك في قاعدة التطوير؛ ينشئه المستخدم عبر npm run owner:create دون بيانات دخول افتراضية.
- دفتر مواد فعلي يحفظ الحركات والأرصدة والتدقيق والأحداث في معاملة واحدة؛ التفاصيل في [تنفيذ دفتر المواد](MATERIAL-LEDGER.md).
- الرصيد الافتتاحي وعكسه للمالك فقط؛ الاستلام للمدير والمالك. المراجع غير الفارغة تمنع تكرار السند للمورد.
- التفاصيل وحدود الضمانات: [حالة الإصدار](IMPLEMENTATION.md).

## المهمة التالية لمن يكمل التنفيذ

1. استكمال T05: تفويضات العامل وواجهة تشغيله وإدارة المستخدمين. صلاحيات التخمير الحالية للمالك والمدير؛ لا تفتح إدارة المصنع للعامل ضمنيًا.
2. T11 تخصيص المعدات وبدء الفرن. تثبيت D04 قبل بنية الحجز، وتمديد stage_runs بترحيل جديد. قيد 008 يفترض أجزاء فرن منتظرة؛ يلزم توسيعه مع قواعد التحويل والرصيد عند بدء/إكمال الفرن.
3. T12/T13 إكمال المراحل والأوزان والتوقف والاستئناف، ثم T14 للتوقف الجماعي. أسباب التوقف وactive/elapsed والمراجعة قبل الاستئناف موثقة في الخطة ولا تعتبر منفذة لمجرد حفظها في الوصفة.
4. T15/T16 عامل outbox وجدولة التنبيهات وتسليمها. الأحداث الحالية دائمة، لكن لا إشعارات مسلمة أو تنبيهات خارج الصفحة بعد.
5. استكمال T07 للتحويل وإعادة المعالجة وإعادة البناء، وT08 للمستهلكات العددية، وT18 للتصحيح بعد الاستخدام. لا تحول الخام إلى دهن بنقل عادي بين صنفين.
6. التفاصيل التنفيذية والمسارات والقيود في [دليل التخمير](FERMENTATION.md). بقية D01–D12 تظل بوابات استخدام حقيقي؛ إعدادات واعتمادات الاختبار لا تحسم قرارات المصنع.

## سجل جلسة 2026-11-05 — الكتالوج والوصفات

- ترحيل 003 للأنواع والأصناف والموردين والوصفات، منع حذف الكتالوج وتعديل إصدارات الوصفة، وهوية النوع/فئة الصنف ثابتة.
- أوامر حفظ مشتركة للأصول والكتالوج، مع التحقق من العضوية الحية قبل إعادة نتيجة طلب قديم.
- أسماء غير مكررة داخل النوع، وفصل raw/finished، وتعطيل النوع يمنع الاختيار النشط وكتابة وصفة جديدة دون إزالة سجله التاريخي.
- قفل الأنواع أولًا ثم الأصناف بترتيب UUID للوصفات؛ نسخة المنتج تضبط إنشاء إصدارين متزامنين.
- فتح قسم المشتريات لإعداد البيانات فقط، مع توضيح غياب الاستلام. صفحة وصفات مستقلة داخل القسم دون إضافة قسم رئيسي.
- أصلحت دورة حياة pool في عامل اختبارات المتصفح، وعزلت عداد الدخول بين الاختبارات في قاعدة الاختبار فقط؛ لم أعطل rate limiting للتطبيق. أضفت رسالة عربية لحالة 429.
- لا بيانات اختبار في قاعدة التطوير، ولا نشر أو وصفات مصنع معتمدة.

## سجل جلسة 2026-11-05 — دفتر الخام والاستلام

- ترحيلان 004/005: سند وبنود ودفعات خام وحسابات وأرصدة وحركات وخطوط وoutbox، مع تحقق مؤجل من التوازن واكتمال الاستلام. طُبقا على قاعدتي التطوير والاختبار.
- خدمة postMovement داخلية تقفل الأرصدة بترتيب ثابت، ترفض السالب وتضمن التوازن لكل صنف. لا API لنقل اعتباطي.
- استلام حتى 25 مادة خام مختلفة، مورد إلزامي للمشتريات، وسبب إلزامي للافتتاحي. نسخة المنتج/النوع/المورد محفوظة بالاسم وقت الاستلام.
- عكس موثق دون حذف؛ يرفض بعد أي استخدام، ويعيد الأرصدة للصفر عند قبول العكس. مرجع المورد يبقى محجوزًا حتى بعد العكس، إلى حين خدمة التصحيح المترابط.
- فصل حفظ الطلب المعلق في hook مشترك للكتالوج والاستلام، مع إبقاء نطاق التخزين مستقلًا لكل حساب ومجال. اختبارات المجالات السابقة نجحت بعد التغيير.
- اختبار 25,000 مع سحبين متزامنين 15,000: نجح واحد فقط، وبقي 10,000. حقن فشل outbox أثبت تراجع السند والرصيد والحركة والتدقيق ومفتاح الطلب معًا.
- تحقق إضافي: عدم تقريب دقة SQL الزائدة، كسور متعددة المواد، صفحات 25+2 دون تكرار، دور المالك الحي قبل إعادة طلب افتتاحي، وإعادة أمر إنشاء بعد عكسه دون زيادة الرصيد.
- لقطات اصطناعية: [تفاصيل المكتب](design/screenshots/receipt-desktop.png)، [تفاصيل الهاتف](design/screenshots/receipt-mobile.png). لم يُنفذ اختبار حمل أو استعادة إنتاجية أو تجربة مصنع حقيقية.

## سجل جلسة 2026-11-05 — الإعدادات واعتماد الوصفة والتخمير

- رابط المعاينة المحلي: http://localhost:3108/login؛ لا رابط استضافة عامة أو حساب دخول افتراضي.
- ترحيلات 006/007/008: إعدادات واعتماد ثابت ومؤشر تفعيل؛ دفعات تخمير وأجزاء ومراحل وحسابات مواد؛ تحقق مؤجل من تطابق الحالة والحركة والرصيد والحدث.
- التخمير يستهلك الكمية المختارة كاملة من دفعة خام واحدة؛ اسم المنتج والوصفة والإعدادات محفوظة. لا إدخال متكرر للمنتج في الفحص أو السحب.
- الجاهزية بفحص بشري بعد الموعد وفق وقت الخادم. انتهاء العداد لا يكمل العملية. السحب ينشئ فرنًا منتظرًا، ولا يبدأ تشغيله.
- اختبارات مثبتة: سحب مكرر بالمفتاح نفسه ينتج أمرًا واحدًا، تنافس سحبين لا يسمح بتجاوز الرصيد، رفض الفحص المبكر، فشل outbox يعيد الرصيد والأمر والتدقيق والطلب، وتغيير التفعيل لا يغير سياسة دفعة سابقة.
- استعادة رد سحب مفقود من المتصفح، ورفض تجاوز الرصيد، وثبات البيانات بعد إعادة التحميل. إعدادات ودقة الوزن واعتماد الوصفة للمالك فقط.
- عزل بناء خادم الاختبار `.next-test` عن المعاينة `.next` بعد اكتشاف تعارض ملفات أنواع Next المولدة. لم تُمس ملفات المشروع لإخفاء أخطاء الأنواع؛ أُعيد توليدها والتحقق منها.
- دليل الاستخدام والقيود: [FERMENTATION.md](FERMENTATION.md). التصميم: [PRODUCTION.md](design/PRODUCTION.md).
- لم تُضف بيانات مصنع حقيقية، ولم يُنفذ تشغيل الفرن أو التوقف والاستئناف أو الإشعارات أو التقارير أو النشر العام.

## إعادة تصميم الواجهة بطلب المستخدم

- اختار المستخدم خلفية فاتحة وجداول واضحة وإدخالًا بخطوات قصيرة.
- تحديث الدخول والتنقل والألوان والجداول والنماذج للواجهات الحالية؛ لا خدمات إنتاج جديدة أو تغيير في الأرصدة والصلاحيات.
- فصل إدخال الاستلام وبدء التخمير إلى ثلاث خطوات، مع مراجعة قبل الحفظ واحتفاظ بالقيم عند الرجوع.
- قوائم اختيار أبسط مع بحث عند الحاجة، وروابط تجهيز واضحة عند عدم وجود بيانات.
