# حالة الإصدار الأولي

هذا إصدار تطوير محلي، وليس نظام مصنع مكتملًا أو جاهزًا للإطلاق الإنتاجي.

## ما نُفذ

- Next.js وReact وTypeScript بإصدارات مثبتة وملف package-lock.
- PostgreSQL تطوير واختبار منفصلان، وحساب تطبيق محدود الصلاحيات واتصال ترحيل إداري منفصل.
- ترحيلات مرقمة مع checksums وقفل يمنع تشغيلها بالتزامن وتراجع المعاملة عند الفشل.
- Better Auth مع جلسات قاعدة بيانات، تسجيل عام مغلق، وفحص عضوية نشطة ودور على الخادم.
- أمر إداري لإنشاء المالك الأول دون كلمة مرور ثابتة؛ لا توجد صفحة تسجيل عامة.
- عرض الأصول وإضافتها وتعديلها وتعطيلها، والبحث والتصفية والصفحات من الخادم.
- رقم أصل تلقائي، ونسخة للسجل، وتدقيق لكل إضافة وتعديل.
- أنواع وأصناف خام/نهائي وموردون، مع اختيار النوع أولًا، أرقام أصناف تلقائية، بحث وصفحات وتعطيل دون حذف.
- وصفات مسودة بإصدارات ثابتة تربط الخام بالمنتج النهائي وتحفظ الأسماء والسياسات تاريخيًا، مع نسخ الإصدار السابق إلى نموذج جديد.
- OpenAPI للمسارات المنفذة ومولد وفحص تطابق؛ عقد المواد للخدمات التالية في MATERIAL-CONTRACT.md.
- مفتاح طلب يمنع تكرار الحركة؛ التعديل بآخر نسخة معروفة يمنع الكتابة فوق تعديل مستخدم آخر.
- تخزين طلب الحفظ المعلق بنطاق المستخدم قبل إرساله، والتحقق من نتيجته دون تكرار عند فقد الرد.
- واجهة عربية متجاوبة، خط محلي، حالات فراغ وخطأ وانقطاع اتصال، وحوار قابل للتشغيل بلوحة المفاتيح.
- عقود أولية للأوزان العشرية الدقيقة، والنسخ، والتوقيت وإنهاء التوقف دون استئناف وهمي.
- استلام خام وأرصدة افتتاحية للمالك، مع دفعات مصدر ودفتر حركة وأرصدة وتدقيق/outbox بمعاملة واحدة.
- عكس الاستلام غير المستخدم بحركة موثقة، وصفحة أرصدة الخام، وأمر مطابقة للدفتر دون تعديل البيانات.

العقود الزمنية ليست تطبيق خط إنتاج: لا توجد بعد خدمة تشغيل فرن أو جدولة إشعارات أو مخزون إنتاجي.

## إعدادات المصنع وبداية الإنتاج

أضيفت إعدادات المالك وتأكيد دقة الميزان، واعتماد إصدار وصفة وتفعيله أو إيقافه دون تعديل التاريخ. قسم الإنتاج ينشئ تخميرًا من مصدر خام واحد، ويحفظ اسم المنتج والسياسة والتوقيت آليًا، ويتيح الفحص بعد الموعد والسحب الجزئي. كل سحب له أمر ومرحلة فرن منتظرة، دون بدء الفرن تلقائيًا. التفاصيل في [دليل التخمير](FERMENTATION.md).

الحفظ يشمل حركة المادة والرصيد والتدقيق وoutbox والطلب في معاملة واحدة. قيود قاعدة البيانات ترفض اختلاف الرصيد أو الحالات أو غياب الحركة والحدث، بالإضافة إلى تحقق الخدمة. أسماء المنتجات والمدد وإعدادات الدفعة تبقى ثابتة عند تعديل الكتالوج لاحقًا.

## ما لم يُنفذ بعد

تفويضات دقيقة للعامل، واجهة إدارة المستخدمين واستعادة كلمة المرور، التحويل التصنيعي من الخام إلى الدهن، مستهلكات المشتريات العددية، تشغيل الفرن وإكمال المراحل والتوقف والاستئناف والمعدات التشغيلية، التنبيهات، المخزون والبيع، التقارير، النسخ والاستعادة الإنتاجية والنشر الفعلي. تصنيف أصل بأنه فرن لا يعني أنه أصبح معدة محجوزة في خط إنتاج.

المشتريات تفتح سجل استلام المواد الخام، مع صفحات الأرصدة والأصناف والموردين والتفاصيل والعكس. خط الإنتاج يتيح التخمير والسحب الجزئي؛ بقية المراحل والتقارير قيد الإعداد.

## الأمان وحدوده الحالية

الأصول والكتالوج والوصفات واستلام الخام وأرصدته متاحة للمالك والمدير فقط؛ الأرصدة الافتتاحية وعكسها للمالك فقط. العامل أو الحساب المعطل لا يقرأها ولا يعدلها. اعتماد الوصفة وتفعيلها وإعدادات المصنع للمالك فقط، والتخمير والسحب الجزئي للمالك والمدير حاليًا. الأوامر تتحقق من origin والمدخلات وحجم الجسم. دفتر التدقيق غير قابل للتعديل أو الحذف بحساب التطبيق، ومكتبة المصادقة تستخدم حد طلبات مخزنًا في قاعدة البيانات.

لا يوجد حاليًا MFA أو تدفق استرداد حساب أو إدارة مستخدمين مكتملة أو مراجعة أمان إنتاجية شاملة. يظل ذلك ضمن T05/T23 قبل الإطلاق. حسابا التطوير والاختبار لا يُستخدمان كحسابات مصنع.

قواعد idempotency الحالية تشمل الأصول والكتالوج والوصفات والإعدادات والاعتماد والتخمير والسحب والاستلام والعكس؛ الاستلام يضيف الدفتر والأرصدة وoutbox في المعاملة نفسها. لا تُعتبر تنفيذًا لـ T07 كله. ضمان عدم التكرار يتعلق بالطلب نفسه ومفتاحه؛ إذا فُقد التخزين المحلي بالكامل يلزم التحقق من السجل قبل تسجيل عملية جديدة.

## أوامر مساعدة

```bash
# إنشاء مالك تفاعليًا (كلمة المرور مخفية)
npm run owner:create

# الاختبار فقط للأوزان والزمن
npm run test:unit

# اختبارات المعاملات والصلاحيات على PostgreSQL الاختبار
npm run test:integration

# إيقاف قاعدة التطوير الخاصة بالمشروع عند عدم الحاجة إليها
docker stop duhn-postgres-dev
```

لا تحذف volumes إلا عند رغبة صريحة في حذف بيانات قاعدة التطوير. db:dev يبدأ الحاوية الموجودة مجددًا؛ لا يعيد إنشاء بياناتها.

إذا نجح إنشاء مستخدم المالك وفشل إسناد عضويته بسبب عطل قاعدة البيانات، لا يُمنح المستخدم صلاحية افتراضية. يتطلب استرداد bootstrap تدخلاً إداريًا موثقًا قبل إعادة الأمر؛ لا يحذف البرنامج حسابات تلقائيًا.

## أثر مراجعة Astra

1. صححت عبارة أن العميل يولد expected_version: العميل يولد المفتاح فقط، ويستخدم نسخة الخادم. خدمة الأصول واختبار إعادة الطلب يطبقان هذا الفصل.
2. أضفت نهاية توقف وسببها مستقلين عن resumed_at، وأفعالًا مسموحة أثناء انتظار الفحص، مع أمثلة اختبارات زمنية. التنفيذ الفعلي للمراحل يأتي لاحقًا.
3. وُثقت ملكية رصيد المواد والمحاولات والتعافي في MATERIAL-CONTRACT.md. نُفذ جزء التخمير والسحب منها، وتبقى خدمات تشغيل المراحل والتحويل؛ لا تثبت اختبارات الإدارة حالات التشغيل الصناعي.

## حدود بيانات الوصفات

المدة والتنبيه ومهلة التأخير بالدقائق أعداد صحيحة، وأساس الوقت active/elapsed منفصل عن continue/require_review. القيم ليست مددًا صناعية افتراضية. لا تعديل أو حذف للإصدار المحفوظ؛ التغيير ينشئ إصدارًا جديدًا. حد التحويل المقترح بين الخام والنهائي والتشغيل الحقيقي يحتاجان اعتماد D01/D02.

عند التعارض تُحدث القائمة ويغلق النموذج لتُفتح النسخة الحالية. الخطأ 503 أو فقد الرد يحتفظان بطلب الاستعادة. أسماء الأصناف فريدة داخل النوع وأسماء الأنواع والموردين فريدة في سجلها؛ الاسم المعطل يبقى محجوزًا لتشجيع إعادة استخدام السجل التاريخي بدل مضاعفته.

## شريحة دفتر الخام

راجع [MATERIAL-LEDGER.md](MATERIAL-LEDGER.md) للقيود وملكية الحسابات وترتيب الأقفال ومطابقة الدفتر. `npm run materials:check` يقرأ الفروق فقط؛ لا يعيد البناء. مصدر البيانات الآن فعلي للخام، لكن مخزون المنتج النهائي والمراحل والإشعارات والتقارير لم تنفذ بعد.

التاريخ تلقائي UTC دون إدخال رجعي، والمرجع غير الفارغ محجوز للمورد حتى بعد عكس السند. التصحيح المترابط بعد الاستخدام والمرتجعات الجزئية ضمن T18. outbox محفوظ ولم يُضف عامل تسليم بعد.
